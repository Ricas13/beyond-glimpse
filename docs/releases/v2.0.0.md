# Beyond Glimpse v2.0.0

Beyond Glimpse 2.0 replaces the Jellyfin static catalogue mirror with a small SQLite-backed catalogue service designed for very large libraries.

## Highlights

- Lightweight initial bootstrap: only browse/search metadata is fetched for the full library.
- Immediate partial availability: every bootstrap page is committed and can be browsed before later libraries finish.
- True server-side pagination: the browser requests only 48 mobile or 96 desktop titles at a time.
- SQLite FTS5 search and server-side genre filters/sorting.
- Rich item metadata is lazy: Overview, cast, studios, ratings, runtime and related detail fields are fetched only when an item is opened.
- Lazy details are cached locally for seven days by default.
- Normal Jellyfin updates use lightweight `MinDateLastSaved` polling every 10 minutes by default.
- Daily ID-only reconciliation catches deletes and moves without rich metadata rebuilds.
- Reconciliation safety guards refuse zero-ID and unexpectedly destructive inventories.
- Poster requests are now exact catalogue ID + image-tag whitelisted before the authenticated Jellyfin request.
- Jellyfin credentials are no longer written into generated Nginx poster configuration.
- Existing 256 MiB hard-bounded ephemeral Nginx poster cache remains.
- Plex and Emby compatibility paths remain available.

## Upgrade

After pulling v2.0.0, rebuild/recreate the Traefik deployment:

```bash
cd /opt/beyond-glimpse
git pull --ff-only
docker compose -f docker-compose.traefik.yml up -d --build --force-recreate
```

v2 creates `/app/state/jellyfin/catalogue-v2.db`; it does not depend on a successful v1 rich-metadata catalogue build.

Follow the initial bootstrap:

```bash
docker exec beyond-glimpse tail -f /var/log/initial-sync.log
```

Check live status at any time:

```bash
docker exec beyond-glimpse python /app/scripts/status.py --server jellyfin
```

After bootstrap completes:

```bash
docker exec beyond-glimpse python /app/scripts/smoke_test.py
```

## Operational defaults

- bootstrap page target: 1,000 lightweight items;
- changed-item page target: 500;
- changed-item interval: 10 minutes;
- watermark overlap: 5 minutes;
- ID inventory page target: 2,000;
- reconciliation interval: 24 hours;
- rich-detail cache TTL: 7 days;
- poster cache ceiling: 256 MiB.

See the README and `CHANGELOG.md` for the complete architecture and configuration reference.
